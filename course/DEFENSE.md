# 综合答辩：用机制、源码与证据回答追问

这是课程原创的项目延伸答辩，不冒称新增公司真题。原 80 道有来源的题仍在主课程。总计 30 分钟：项目陈述 3 分钟，以下八题 20 分钟，现场排障 7 分钟。每题 0—3 分，共 24 分：0 为概念错误或虚构实现；1 为能定义；2 为能解释机制和源码；3 为能用反例、运行证据和边界支撑。

## 1. 这个项目为什么需要 Agent，哪些地方不需要？

参考回答：模型负责在受限工具和问题中选择后续动作，检索提供实际证据；执行器控制调用、预算与终态；确认和摘要由账户权限、用户与确定性程序控制。普通知识问答可以先从固定检索起步，不能因使用了 Agent 就假设它更好。

追问：为什么基线里固定 BM25 优于 offline？后者是简单关键词决策夹具，路由覆盖有限；这不评价真实模型能力。加分证据是 benchmark 的逐题结果，扣分项是声称 14/40 证明“LLM 不如 BM25”。

## 2. 请不看代码画出工具调用往返。

参考回答：输入与工具合同→模型提议→校验名称/参数/身份→实际执行→按 call_id 回传观察→再次决策→校验终态。Responses 与 Chat 的封装不同，必须显式适配。call_id 去重只覆盖一次回合，不能替代业务幂等。

追问：记录到 search_knowledge 就证明查库成功了吗？没有，决策记录发生在执行前。请指出 runtime-traces 中第二轮真正收到观察的证据。不能展示或索取私有思维链来充当执行证明。

## 3. 候选引用来自原文，为什么还要用户确认？

参考回答：字符串存在只能证明来源，不能证明字段分类、时效或个人陈述医学成立；否定和“未提供”也不能等价。确认绑定来源回合、候选和版本，摘要只读取当前确认事实。

追问：旧版本审批为何拒绝？更正后审批对象已变；不能让旧按钮授权新草稿。源码定位 repository/policy，行为证据用确认、更正、撤回测试。说“Pydantic 已通过所以可信”不得分。

## 4. 检索满分而回答错误，按什么顺序排查？

参考回答：核对资料存在与许可、切块完整性、召回候选、排名、送入模型的证据、引用选择、结论支持和最终任务结果。Recall@4 满分允许第一名错误，MRR、精确证据选择和答案质量评价不同。

追问：未知题为什么会误引？词面匹配有分数不等于语义支持；RRF 名次分不能当可答概率。给出一条报告里的实际失败，并设计开发集/留出集验证方案。只回答“换向量库”不足以过关。

## 5. 相同请求重试、同版本竞争和租约竞争有何区别？

参考回答：request_id 与正文哈希判断原操作；expected_version 防旧状态写回；lease 防旧资格提交。短事务认领、事务外运行、短事务条件提交，操作结果与快照原子保存。

追问：旧工作者提交已经更新快照，再发现租约失效怎么办？同一事务回滚，两条更新不能拆开。用 crash-recovery 的版本 0→1 及旧资格错误码作证，不能承诺模型调用 exactly-once。

## 6. 为什么 HTTP 200 或 SSE accepted 不代表任务成功？

参考回答：200 可以是已提交的降级；accepted 只表示处理开始。UI 需要完整 committed/done 合同；断流保留原请求身份。请求被明确版本拒绝与结果不确定，需要不同重试策略。

追问：远端已经返回但本地超时是否免费？不能保证。总 deadline、HTTP 重试和平台账单分别记录。进度不伪造 Token，降级不假装重新检索。

## 7. 如何证明系统能上生产？

参考回答：当前只能证明已执行的边界：SQLite、受控模型夹具、协议 wire 测试、真实本机 HTTP、基础 UI 与课程实验。真实供应商、真实 Embedding、PostgreSQL、容器、多副本和长期 SLO 需要相应环境和数据；医疗服务还有专业审核流程。

追问：本机 p95 很低为什么不能推 QPS？样本短、offline 无模型等待、并发模型不同、排队/配额未覆盖。明确没测过比报一个猜测容量更可信。

## 8. 你会怎样演进项目，而不让复杂度失控？

参考回答：先完成真实平台合同与任务评测，再按失败归因改路由、证据选择和未知判断；补有盲审或独立留出题的回归，测量收益/费用/延迟。只有单主体确实无法完成可分工任务时再考虑多 Agent，同时明确共享状态、审批与协作成本。

追问：会不会把失败题直接加入 Prompt？可以用于开发，但不能继续当未见测试集。应记录版本、暴露数据污染并另设留出集。

## 七分钟现场题

给学习者一条失败：用户更正资料后，旧请求晚到。要求先画时间线，再定位 expected_version 与 lease 的不同职责，最后运行旧提交回滚测试。评分各 1 分：输入/版本清楚、故障窗口清楚、条件更新正确、原子事务正确、重试身份正确、执行证据明确、不虚构平台效果。满分 7 分，与上面概念评分分别报告，不用一个总分遮住短板。
