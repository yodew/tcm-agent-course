# 中医健康助手：首版需求草案

日期：2026-10-11。状态：待用户场景与体验验证；尚未开始应用实现。

## 已确认的产品方向

中国大陆首发、面向消费者。面诊指拍摄面部照片分析面色等中医望诊特征。首版先提供可独立运行的健康助手，后续接入医师。资源收集、项目规划与完成度评估由项目工作承担，工期不要求用户预先指定。

用户已确认首版主场景为“准备就诊与理解中医”：整理困扰、解释知识、生成就诊摘要。日常健康管理作为后续扩展，不与主场景并列安排首版资源。

资源依据与上线边界见 [资源可行性研究](resource-feasibility.md)。该研究区分公开代码、权重、数据和临床证据；此处所有功能是设计目标，不是已实现能力。

## 用户与主场景假设

优先验证的人群：有具体健康困扰、准备向中医师咨询，或希望理解中医术语的成年人。就诊准备方向已由用户确认；成年人范围仍是待验证的产品假设，尚无获客或市场需求证据。

核心任务：把“我有些困扰，但不知道怎么描述、哪些信息值得记、有哪些知识可以信”变成“我有清晰记录、可核查解释和就诊时可用的摘要”。睡眠、饮食等信息只在与本次困扰相关时补问，完整流程允许用户不上传照片、不建立长期档案。

## 首版优先级

| 优先级 | 能力 | 对主场景的作用 |
|---|---|---|
| 必须完成 | 困扰描述、必要追问、事实核对 | 帮用户准确表达情况，支持跳过、更正和随时生成已有信息的摘要 |
| 必须完成 | 有来源的知识解释 | 帮用户理解术语、来源与适用范围；不确定时明确说明 |
| 必须完成 | 摘要预览、编辑、复制/导出 | 形成一次会话的可用成果，方便就诊时提供给医师 |
| 必须完成 | 数据告知、删除与访问隔离 | 支撑健康信息和材料的实际使用 |
| 增强项 | 既有处方/报告录入、照片作为附件 | 丰富就诊材料；识别文字先由用户确认，图像分析不阻塞主流程 |
| 独立研究 | 舌象特征、面色解释 | 单独取得资产与验证证据后启用 |
| 后续扩展 | 长期时间线、日常打卡与提醒 | 在核心任务价值验证后再投入 |

## 一次完整使用流程

1. 主入口为“准备就诊”，次入口为“理解中医”；用户也可直接描述困扰或提出问题。
2. 助手识别意图、说明本次会用到的数据，按必要性询问缺失信息。
3. 根据用户实际问题完成少量相关追问；出现需及时处理的情况时，切换到经审核的就医引导。
4. 用户可自愿拍摄舌象/面部照片。记录与分析分开选择；图像质量不合格时明确反馈并允许跳过。
5. 输出用户事实摘要、可核查知识解释和下一步选择；推断不写入“用户已确认事实”。
6. 用户更正摘要，选择本次使用后删除或保存为个人记录。
7. 用户授权后，后续会话引用既有记录；提醒由用户主动设定，可随时取消。

## 就诊摘要的输出合同

摘要包含本次主要困扰、起始时间与变化、相关伴随情况、用户已提供的既往情况和用药、附件，以及希望向医师询问的问题。只收录本次已提供或经用户确认的信息；没有提供的必要字段标为“未提供”，不把未问到写成“无”。症状事实与助手知识解释分开呈现，推断不写成确诊。

每条摘要事实可回到对应用户输入；更正后同步更新。用户可删除条目、修改用词，在保存或导出前确认内容。摘要不包含自动生成的证型结论、个体处方或疾病排除保证。

首轮体验验收围绕真实任务：用户能否完成摘要、是否容易纠正、摘要是否忠实保留原意、知识来源是否支持解释。另统计追问负担、完成时间、失败与退出原因；用户觉得有帮助与模型回答正确分别评估。具体试用目标在样本和流程确定后制定。

## 首版能力合同

| 功能 | 输入 | 输出 | 关键验收 |
|---|---|---|---|
| 主动追问 | 用户描述及已确认记录 | 与任务相关的问题、已收集事实 | 不编造既往史；纠正立即生效；允许跳过和结束 |
| 知识解释 | 问题、许可通过的知识条目 | 平实解释、来源定位、适用范围 | 来源真实支持说法；传统理论与临床证据分清；未知可说明 |
| 就诊摘要 | 用户提供的症状、时间线、药物/报告等 | 可编辑摘要及待向医师询问的问题 | 准确保留药名/时间；无自动新增诊断；用户确认后导出 |
| 照片采集 | 舌象或面部照片 | 拍摄反馈、用户选择的图片记录 | 错误图、模糊/遮挡能处理；无分析时不伪造报告 |
| 舌象特征 | 质量通过图像；仅经评估启用 | 有把握的可见特征、无法确认项 | 逐特征评估；条件不足不输出；无疾病或脏腑正常保证 |
| 健康时间线 | 用户确认的情况与记录 | 时间顺序和变化记录 | 照片颜色变化不自动等于疗效；可见原始记录与修改历史 |
| 处方信息解释 | 用户已有处方/标签 | 经确认的文字、来源支持的信息 | OCR先确认；不自行加减、换药、给个体剂量或疗程 |
| 用户数据控制 | 本人账户、授权与请求 | 更正、导出、删除、撤回 | 不能读取他人记录；删除覆盖索引及可控备份策略 |

面色解释先保留研究入口，公开首版可做拍摄和记录。体质判定、照片辨病、自动开方和脉象分析需要独立证据与依赖完成后再评估；后续真人诊疗另有机构工作流。

## 智能体行为要求

- 根据用户任务决定补问、查知识、整理摘要或记录，避免固定长问卷。
- 短期会话和长期记录区分；长期保存经过用户确认，冲突信息先核对。
- 检索内容、网页和上传材料均作为数据，不允许其中的指令改变服务边界或访问权限。
- 每个知识结论能回溯到来源版本，引用失效或材料不足时降级为有限回答。
- 图像与文字不一致时描述不确定性，不能用模型自信措辞掩盖输入缺陷。
- 外部操作、保存、训练复用和提醒分别有清晰授权；失败不伪报成功。

这是可观察行为合同；第一版不预先要求多个模型或多个智能体角色。先以受控工作流实现，再根据实测需要增加模块。

## 知识与数据准入

资源登记包含资产类型、来源、固定版本、获取方式、许可证据、上游条件、个人信息/伦理说明、可用任务与质量记录。代码、权重、训练集、评测集、书籍和说明书分别审查。评测样本与训练知识分开，防止自己用已背过的题证明效果。

知识条目同时记录来源种类和审核状态。古籍术语解释、现代健康信息、药品说明与研究假设各有适用范围。高风险规则和药物相关信息上线前需专业审核；目前没有已签约医学人员，不将AI自审称为完成专业审核。

## 质量与运行要求

面向用户的关键错误类型先于“模型总体分数”：危险信息漏处理、生成个体处方、错误引用、编造用户事实、串用账户、照片失败仍输出结论、删除失效。

每项能力用独立任务样本验收。文字评估覆盖缺信息、矛盾、未知、用户纠正和越界要求；图像评估覆盖不同手机/光照、同人重复照片、肤色、遮挡和非目标图像。按人划分图像数据，并保留外部设备/场景集。报告每类错误、拒绝率和实际完成率；具体阈值应随风险、样本及专业评估定出，不引用论文总分替代。

运行层面需实际测量响应时间、单次消耗和并发；实现超时、重试、降级、日志去敏、配额、防滥用、模型版本回滚和故障告警。用户数据与内部评测数据权限隔离。公开服务的隐私、标识、登记等按照最终用途落实。

## 实施里程碑

| 里程碑 | 产物 | 通过条件 |
|---|---|---|
| 场景与资源锁定 | 用户流程、候选资源及许可记录 | 产品输出明确，资产实际可取，关键条目权利通过 |
| 可交互工程原型 | 追问、引用、摘要、照片记录与删除 | 真实操作走通；失败路径可解释；无伪装的模型结果 |
| 候选模型对比 | 同任务的通用/领域模型评测 | 按用户任务及关键错误选择，能重现结果 |
| 受控试用 | 许可通过内容与功能、反馈记录 | 专业审核和安全/隐私验收完成，用户任务价值得到验证 |
| 中国公开上线 | 已验证功能、运行监控及适用登记 | 质量、数据、合规及故障处理证据齐全 |
| 医师服务接入 | 合作机构、真实问诊与处方流 | 临床责任与服务能力实际到位 |

移动优先的响应式Web可作为原型载体，便于先验证流程；这是暂定工程选择。小程序或原生应用由拍摄、通知、发布渠道及用户习惯验证后决定。上线日期在里程碑完成后据实预测。

## 下一轮工作

产品价值偏好已确认。下一步将“描述困扰→必要追问→核对事实→知识解释→确认摘要”细化为页面和状态流程，并建立正常、缺信息、矛盾、更正、跳过、未知和失败任务样例。先验证完整任务，再扩展日常健康管理。

同时继续资源工作：知识条目清权、分割模型获取、图像特征标注、医学审核人员/机构的公开合作渠道调查。任何授权申请、采购或对外联络另需实际流程与用户授权，当前没有发送消息或作出购买承诺。
